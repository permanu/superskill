## Notes / follow-ups (outside verifier ownership)

- `sec-urlcomponents`: the Good fixes query/fragment injection and invalid-character encoding (`?`→`%3F`, `#`→`%23`, space→`%20`), but `URLComponents.path` leaves `..` and `/` literal — the harness produces the identical `https://api.example.com/users/../../admin` for the Bad and Good forms. The Why's traversal sentence is accurate about concatenation and the cited source backs the encoding mechanism, so the rule is verified as written; if traversal defense is in scope, the Why should be narrowed or the segment validated/encoded in a follow-up edit.
- MetricKit migration caveat: the current SDK marks `MXMetricManager` `API_DEPRECATED("Use MetricManager instead.", ios(13.0, API_TO_BE_DEPRECATED), macos(12.0, API_TO_BE_DEPRECATED))` — a soft deprecation that emits no warnings today, and Apple's docs still expose the MXMetricManager API collection. The four `metrickit` rules are valid for the current SDK; when the deprecation lands they will need the Swift-native `MetricManager`/`MetricReport` API.
- Other batches in flight: the validator reports `index-missing` errors for `mem-*` and `proj-*` files not listed in INDEX (not this batch). INDEX header `Rules: 96 (verified: 70)` predates this batch; after these 24 flips it should read `verified: 94` (index owner's action). The `mem-*` files are also absent from INDEX, which the validator flags separately.
