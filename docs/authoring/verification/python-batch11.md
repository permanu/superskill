## Non-blocking notes

- `num-statistics-mean`: the Why's "converts exact types to float along the way" holds for `int` inputs (`mean([1,2,3])` -> `2` vs `sum/len` -> `2.0`; `mean([10**400, 10**400])` -> exact int vs `OverflowError: integer division result too large for a float`), but not for `Fraction`/`Decimal`, which `sum/len` preserves exactly (docs examples reproduce: `13/21`, `Decimal('0.5625')`). Rewording to "int inputs" would tighten it; core advice and sourced claims stand.
- `const-sentinel-object`: "survives pickling" is true only in the can-be-pickled sense. A bare `object()` unpickles to a new instance, so an identity check fails on a round-tripped sentinel (`pickle.loads(pickle.dumps(_MISSING)) is _MISSING` -> False, `==` -> False); PEP 661's motivation cites this as a known drawback of the `object()` idiom. Suggest dropping/re-wording the clause (module-level references are re-imported by name, which is the only identity-preserving path).
- `const-env-snapshot`: the summary's "never refreshes" should read "does not refresh automatically" - `os.reload_environ()` (new in 3.14, on the same docs page) explicitly refreshes the cache. The captured-at-import semantics and the rule's advice are unaffected; probe confirmed `os.putenv` is not reflected.
- `perf-operator-getters`: the Bad shows a list comprehension, not the Python-level lambda the Why contrasts. Benchmarks on 3.14.6: `map(itemgetter(0))` vs comprehension is workload-dependent (10k rows: 0.032 s vs 0.035 s for map; 1M rows: 0.087 s vs 0.046 s for map), while the documented advantage is unambiguous for sort keys (`sorted(key=itemgetter(0))` 0.070 s vs lambda 0.344 s, 100k rows). Claims are doc-quoted and the Good is documented usage; a lambda Bad would match the Why better.
- `perf-join-strings`: for an empty input the Bad returns `""` and the Good returns `"\n"`; outputs are identical for non-empty input. The PEP 8 claim (join vs `+=`) is unaffected.
- `const-regex-compile`: the docs say "the most recent patterns ... are cached"; "bounded" is a CPython implementation detail (`re._MAXCACHE` is 512), not a docs claim. Non-blocking.
- `pat-entry-points`: the Bad is a hardcoded name list while the Why mentions importing all plugins to find one; the hardcoding/scanning contrast still matches the PyPA guide's metadata section.
- `pat-total-ordering`: the Bad defines only `__eq__`/`__lt__` (so `<=` raises `TypeError`) rather than the "six methods" the Why mentions; the derived-method behavior and the decision verified.
- `INDEX.md` header (`Rules: 287 (verified: 253)`) and the batch status line are stale after these 23 flips; updating the index is outside verifier ownership.
